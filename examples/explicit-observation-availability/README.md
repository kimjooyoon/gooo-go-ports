# Explicit observation availability

This opt-in profile keeps raw recorded values intact and declares separately whether each context value was observed. The literal `UNKNOWN` is a valid opaque value when explicitly `SUPPLIED`; an `UNOBSERVED` value is never evidence of equality or change, whatever its spelling.

`ports/tool-origin/explicit_availability.gooo` owns collection and definition decisions. It checks the complete bound column roster and compares a context pair only when both values are supplied. Structural collection failures and independently observed differences retain their existing priority. Missing required context prevents a complete-context decision. A target alias whose page backend revision is unavailable has `ORIGIN_UNOBSERVED`; its unknown raw text proves neither same nor changed origin. Known host, connection or original-name differences remain `ORIGIN_CHANGED`, and duplicate names and alias presence remain separate facts. For `ORIGIN_UNOBSERVED`, a concrete collection failure keeps its existing repair or recollection action; `OBTAIN_ORIGIN_OBSERVATION` applies when collection context is complete or unknown. Missing policy prevents a binding match; optional timestamps add no new equality or completeness requirement. `explicit_observation.gooo` explains each field using the same availability rules. Invalid declarations, including `SUPPLIED` with empty text and `LEGACY_TEXT`, fail the new domain profile.

Row-to-page indices are mechanically projected from each original `RowSource`. Gooo validates their bounded lengths, ranges and sides; it does not reverse a hash or authenticate the supplied source mapping.

The public adapter binds an exact sidecar to the original input and normalized policy hashes, validates the complete document/pointer roster, and projects raw values and indices. It performs no sentinel replacement. See the [consumer guide](../recorded-catalog-comparison/README.md) for the template helper and `--definitions --diagnostics --availability` CLI. Existing v1 sources, generated packages and callers retain their behavior.

## Finite evidence

- 40 collection/definition cases cover supplied literal `UNKNOWN`, unavailable text including empty and nonempty strings, asymmetric comparisons, known differences alongside missing context, pagination failures, optional timestamps, unavailable policy, malformed states, and incorrect column bindings. Collection outcomes are authored finite literal anchors; an independent Go reference computes alias identity/presence and definition relations and the 32-field result. This is not a universal collection oracle.
- 12 diagnostic cases use a separate Go implementation. Both profiles execute the original Gooo with compiler `205896a413e5dea92366309c35ae85e542d055f6` and Go 1.27.3, then replay each execution's own receipt. Readers verify exact source, typed fields, inputs, outputs, producer identities and replay parent bytes. Five receipt mutations per profile must be refused.
- Thirteen synthetic API exports are checked against independent expectations and the original Gooo. Every one of their 34 field diagnostics is independently recomputed. An optional, separately labeled retained Compiler Explorer observation preserves its original input hash, retrospective basis, and twenty unavailable required fields. It is not an independent adopter or a new capture-time observation.

Run `verify.py --compiler /absolute/gooo --go /absolute/go --out /fresh/output` for the two finite profiles and exact generated-asset checks. Existing caches can be selected with `--go-cache` and `--module-cache`; no network or model is used. `--prepare-generated` writes new assets only into the output directory for review. Each owned child has a bounded lifetime and records wait, stream EOF and process-group closure.

`verify_consumer.py` accepts the same toolchain/output/cache options plus `--synthetic-export /absolute/export.json` and optional `--retained-ce-export /absolute/export.json`. The Go module's export tests write these files only when requested, without overwriting an existing file. Native/replay comparison is separate from the API/CLI race tests and from full repository CI.

Matching supplied values do not authenticate a producer, establish behavior equivalence, authorize execution, or perform a live effect. Those claims remain false in every result. `remote_atomicity` remains `UNKNOWN`.
