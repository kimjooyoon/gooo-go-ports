# 공개 Go → Gooo 이식 로드맵

작은 순수 함수를 실제로 사용하는 패키지로 옮기고, 원본과 다른 지점을 설명하며,
막힌 표현은 최소 재현 자료로 남긴다. 컴파일러 개발에 대한 기여는 이 사용 근거에서 출발한다.
시작 조합은 Go **1.27.2**, Gooo **0.6.24-dev** 소스
`366ee6ef8f9d2b9b57331dfd26b6f908c0289851`이다.

## 우선순위

| 순서 | 목표 | 다음 단계로 넘어갈 근거 |
| --- | --- | --- |
| 1 | `http.StatusText`, utf8 3개, utf16 4개로 첫 8개 활동 제공 | 원본 파일·버전·라이선스 연결, 경계·음수·잘못된 서로게이트·전체 byte 값의 원본 비교, 실제 네이티브 실행과 저장 재실행 |
| 2 | 여러 이식 패키지를 가져오는 작은 응답/[Unicode 검사 앱](../examples/unicode-inspector/README.md) | Unicode 앱은 기존 UTF-8·UTF-16 포트를 조합. 원본 비교 334개와 영역 밖 거부 12개를 기존 포트와 따로 집계하고 입력만 제공한 실행도 확인 |
| 2a | `math/bits`의 8비트 순수 함수 5개와 ByteSummary 앱 | 각 함수의 byte 전체 256입력 원본 비교, 비트 연산을 대체한 산술의 범위 명시, 저장 재실행 |
| 2b | `image/color` RGB↔CMYK 두 함수와 [색상 왕복 검사 앱](../examples/color-inspector/README.md) | 원래 uint8 3/4성분 전체 입력 범위 보존, 독립 Go 기대값·정수 버림 경계·거부 계약·저장 재실행, 복원 RGB의 채널별 차이 공개 |
| 2c | `math/bits.RotateLeft8`와 [바이트 회전 검사 앱](../examples/byte-rotation/README.md) | byte × signed int64 입력 보존, 정규화된 2,048쌍과 원래 회전 수의 경계·표본 비교, 복원·1비트 개수 확인, 브라우저 입력·공유 |
| 3 | `strings.Index`/`Count`, UTF-8 순회 등 반복이 필요한 문자열 함수 조사 | `for`/`range`, 바이트 읽기, 루프 종료·입력 제한의 재현. Text 슬라이싱 지원만으로 문자열 전체 지원을 선언하지 않음 |
| 4 | `encoding/hex`의 제한된 인코딩·디코딩부터 바이트 패키지 확장 | byte 배열/슬라이스, 출력 구성, 잘못된 문자와 길이에 대한 오류 계약, 비트 연산 또는 검증된 산술 표현 |
| 5 | Google의 `google/uuid` 파싱·표시·버전/variant 부분 이식 | 원본 형식별 입력과 오류를 보존하고 16바이트 값을 표현할 타입, 반복, 인덱싱, hex 처리가 확보될 것 |
| 6 | UUID 생성, I/O·동시성·상태가 필요한 라이브러리 검토 | 난수·시계·외부 효과의 출처와 실패 모델, 상태·인터페이스·error 표현을 먼저 설계하고 순수 계산과 경계를 분리 |

첫 단계의 정확한 함수 목록과 API 차이는 [언어 관측](language-assessment.md)에 있다.
기존 gooo-standard-library의 숫자·논리·접두사/접미사 함수는 재사용 대상으로 두고
복제해서 이식 수를 늘리지 않는다. 첫 8개 함수의 완료는 세 Go 패키지 전체의 완료가 아니다.

`google/uuid`는 v1.6.0을 조사 기준으로 삼는다. 이 버전이 최신이라는 뜻은 아니다.
원본 [uuid.go](https://github.com/google/uuid/blob/v1.6.0/uuid.go)는 `[16]byte`,
바이트 인덱싱, 반복, hex 변환과 `(UUID, error)`를 사용한다.
Parse와 Validate의 허용 형식·오류가 다르므로 하나의 느슨한 검증 함수로 합치지 않는다.
[version4.go](https://github.com/google/uuid/blob/v1.6.0/version4.go)의 난수 생성은
`io.Reader`와 실패 결과를 포함한다. 초기 파싱 포트의 범위에 생성 기능까지 포함하지 않는다.
실제 착수 시 원본 커밋과 라이선스를 고정하고 현재 구현과 달라진 내용을 다시 확인한다.

## 포트마다 남길 근거

1. 원본 저장소·버전·커밋·파일·함수·라이선스와 지원 입력 범위를 기록한다.
2. 동작을 `.gooo`에 구현한다. 수작업 Go는 입력 전달, 원본 오라클, 결과 비교와 기록 저장을 맡는다.
3. 먼저 기대값과 비교 범위를 정한다. 경계값·오류·빈 입력·확정 seed의 추가 입력을 포함하고
   원본 타입 변환에서 범위를 넘는 값은 별도 계약으로 분리한다.
4. 고정한 컴파일러로 생성하고 실제 실행한 뒤 저장 재실행을 비교한다. 생성 SHA,
   원본 SHA, 도구체인, 입력·결과와 실패를 함께 남긴다.
5. 함수 수, 고유 입력 수, 네이티브 실행 수, 재실행 수를 구분한다. 유한 테스트 결과를
   임의 입력의 정확도·속도 우위·전체 언어 호환성으로 바꾸어 표현하지 않는다.

원본 코드를 분석해 번역하거나 구조를 바꾼 부분은 각 파일에 출처와 수정 내용을 표시한다.
원본의 저작권·라이선스는 프로젝트 자체 라이선스와 함께 보존한다.

## 언어 개발로 되돌리는 최소 재현

지원되지 않는 기능은 `probes/` 아래 독립된 `.gooo` 예제로 축소한다. 초기 재현은
[loop.gooo](../probes/loop.gooo), [byte-index.gooo](../probes/byte-index.gooo),
[bitwise.gooo](../probes/bitwise.gooo)이며 [tools/probe.sh](../tools/probe.sh)로 실행한다.
명령과 보존 자료는 [probes/README.md](../probes/README.md)에 정리한다.
후속 예제에는 필요한 동작, 작은 Go 기준 구현, 실행 명령, 컴파일러 빌드 JSON,
실제 종료 코드·stdout·stderr와 기대 결과를 짝지어 남긴다.
`check`가 통과해도 `body-codegen` 또는 실제 실행이 실패하는 경우 단계를 구분한다.
일반적으로 지원되지 않는 기능, 문서와 다른 동작, 회귀 오류를 각각 설명한다.

예제와 언어 버전은 함께 고정한다. 새 컴파일러에서 거절 결과가 바뀌면 성공으로
자동 승격하지 않고 생성·원본 비교·재실행을 다시 확인한다. 임시 Go 구현으로 계산을
우회한 뒤 Gooo 포트가 완료됐다고 기록하지 않는다.

재현 자료가 완성되면 관련 upstream 이슈를 먼저 확인하고, 최소 예제와 정확한 기대/실제
차이를 붙인 이슈 또는 PR 초안으로 정리한다. 이 문서는 향후 기여 절차이며 실제 이슈·PR을
게시했다는 기록은 아니다. 컴파일러 변경은 해당 저장소의
[기여 계약](https://github.com/kimjooyoon/meta-ontology-go/blob/366ee6ef8f9d2b9b57331dfd26b6f908c0289851/AGENTS.md)에
맞춰 별도 검증한다.
